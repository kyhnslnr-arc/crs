Amended Common Reporting Standard (CRS)

XML Schema v3.0 Schema Diagrams

User Guide for Tax Administrations

Schema Version: 3.0

The following diagrams represent the structure of the CRS XML Schema v3.0 as published by the OECD. This document excludes Sponsor, Intermediary, and Pool Report elements, as those are not used in CRS reporting scenarios. Only elements actively used in CRS reporting are documented.

Chapter 1: Overall CRS_OECD Structure

Diagram: Overall CRS_OECD Structure Diagram
Page Reference: 43-44
Description: Root-level structure showing the overall XML Schema hierarchy for the CRS message. This is the top-level element that wraps the entire CRS message structure.

MandatoryCRS_OECDElement: xsd:element
@version (Optional): string, minLength=1, maxLength=10
Namespace: urn:oecd:ties:crs:v3
Children (2 elements required):
  • MessageSpec (1..1)
  • CrsBody (0..unbounded)

Chapter 2: MessageSpec Element (Page 44-45)

Diagram: Message Specification Element Structure Diagram
Page Reference: 44-45
Description: The message specification element identifies the sending tax administration and contains metadata about the message.

MessageSpec Type: MessageSpec_Type
Mandatory Children:
  • MessageType (1..1) – Defines the type of message
  • MessageRefId (1..1) – Unique identifier for this message
  • MessageTypeIndic (1..1) – Type of message content (CRS701 = new, CRS702 = correction, CRS703 = no data)
  • ReportingPeriod (1..1) – Reporting year
  • Timestamp (1..1) – Message creation timestamp
Optional Children:
  • SendingCompanyIN (0..1)
  • TransmittingCountry (1..1)
  • ReceivingCountry (1..1)
  • Warning (0..1)
  • Contact (0..1)
  • CorrMessageRefId (0..unbounded)

Chapter 3: CrsBody Element (Page 45-46)

Diagram: CRS Body Structure Diagram
Page Reference: 45-46
Description: Container element for the reporting financial institution and account reports. This is the main body of the CRS message.

CrsBody Type: CrsBody_Type
Mandatory Children:
  • ReportingFI (1..1) – Reporting Financial Institution
Optional Children:
  • ReportingGroup (0..unbounded) – Account report groupings

Chapter 4: Reporting Financial Institution (Page 46-47)

Diagram: Reporting Financial Institution Structure Diagram
Page Reference: 46-47
Description: Identifies the reporting financial institution that is reporting accounts to tax authorities. This is the entity that sends the CRS message.

ReportingFI Type: CorrectableOrganisationParty_Type
Mandatory Children:
  • DocSpec (1..1)
  • Name (1..unbounded)
Optional Children:
  • ResCountryCode (0..unbounded)
  • IN (0..unbounded)
  • Address (0..unbounded)

Chapter 5: ReportingGroup and AccountReports (Page 47-48)

Diagram: ReportingGroup and AccountReport Structure Diagram
Page Reference: 47-48
Description: Structure showing how account reports are organized within the reporting group. Multiple account reports can be included for different financial accounts.

ReportingGroup Type: xsd:complexType (inline)
Mandatory Children:
  • AccountReport (1..unbounded) – Individual account reports

Note: Sponsor and Intermediary elements are available in the schema but are not used in CRS reporting scenarios. They are reserved for future use.

Chapter 6: CorrectableAccountReport (Page 48-49)

Diagram: Correctable Account Report Structure Diagram
Page Reference: 48-49
Description: Defines the structure of an account report that can be corrected. This is the core element describing individual financial accounts.

CorrectableAccountReport Type: xsd:complexType
Mandatory Children:
  • DocSpec (1..1)
  • AccountNumber (1..1)
  • AccountHolder (1..1)
  • AccountBalance (1..1)
  • DDProcedure (1..1)
  • AccountType (1..1)
Optional Children:
  • ControllingPerson (0..unbounded)
  • Payment (0..unbounded)
  • JointAccount (0..1)

Chapter 7: History and Corrections (Page 49-50)

Diagram: Message Correction and History Structure Diagram
Page Reference: 49-50
Description: Shows how corrections are handled in the CRS schema. Messages can be corrections of previous messages, with proper references maintained.

CorrMessageRefId (in MessageSpec) Type: string (minLength=1, maxLength=170)
Corretion Message Content:
  • MessageTypeIndic: CRS702 (correction)
  • CorrMessageRefId: Points to 1 or more previous messages
  • MessageType: CRS701 (new information)
  • DocTypeIndic: OECD1 (initial) or OECD2 (correction)

Chapter 8: Account Number Specification (Page 50-51)

Diagram: Account Number Element Structure Diagram
Page Reference: 50-51
Description: Defines the structure of account numbers used in CRS reporting. Account numbers can be of various types depending on the account category.

AccountNumber Type: FIAccountNumber_Type (complex content type)
Mandatory Attributes:
  • AcctNumberType (crs:AcctNumberType_EnumType)
Optional Attributes:
  • UndocumentedAccount (boolean, default=false)
  • ClosedAccount (boolean, default=false)
  • DormantAccount (boolean, default=false)

Chapter 9: DocSpec Document Specification (Page 51-52)

Diagram: Document Specification Structure Diagram
Page Reference: 51-52
Description: Document specification element that identifies and classifies the type of report within the CRS message.

DocSpec Type: stf:DocSpec_Type
Mandatory Elements:
  • DocTypeIndic (required)
  • DocRefId (required)
DocTypeIndic Values:
  • OECD1 – Initial report
  • OECD2 – Correction report
  • OECD0 – Resend (when no changes required)

Chapter 10: Account Holder Types (Page 52-53)

Diagram: Account Holder Entity Structure Diagram
Page Reference: 52-53
Description: Structure of account holders, which can be individuals (natural persons) or organisations (passive non-financial entities).

AccountHolder Type: AccountHolder_Type
Optional Child (0..unbounded):
  • EquityInterestType (repeated)
Mandatory Children:
  • SelfCert (1..1)
Choice Element (1..1):
  • Individual (PersonParty_Type)
  • Organisation (OrganisationParty_Type)

Chapter 11: Individual Person Structure (Page 53)

Diagram: Individual Person Structure Diagram
Page Reference: 53
Description: Structure for identifying individual persons within AccountHolder. Contains personal identification, residence information, and birth details.

Individual Type: PersonParty_Type
Mandatory Children:
  • ResCountryCode (1..unbounded)
  • Name (1..unbounded)
Optional Children:
  • TIN (0..unbounded)
  • Address (0..unbounded)
  • Nationality (0..unbounded)
  • BirthInfo (0..1)

Chapter 12: Organisation Structure (Page 53)

Diagram: Organisation Structure Diagram
Page Reference: 53
Description: Structure for identifying organisations within AccountHolder. Used for passive non-financial entities (NFE) and other reporting organisations.

Organisation Type: OrganisationParty_Type
Mandatory Children:
  • Name (1..unbounded)
Optional Children:
  • ResCountryCode (0..unbounded)
  • IN (0..unbounded)
  • Address (0..unbounded)

Chapter 13: Controlling Person (Page 54)

Diagram: Controlling Person Structure Diagram
Page Reference: 54
Description: Structure for identifying controlling persons for organisations. Used in CRS reporting for entities that control the account.

ControllingPerson Type: xsd:complexType
Mandatory Children:
  • Individual (1..1)
  • SelfCert (1..1)
Optional Children:
  • CtrlgPersonType (1..unbounded)

Chapter 14: Payment and Account Balance (Page 54-55)

Diagram: Payment and Account Balance Structure Diagram
Page Reference: 54-55
Description: Financial data elements that describe payment amounts and account balances. These are key data points in CRS reporting.

Payment Type: crs:Payment_Type
Mandatory Children:
  • Type (crs:CrsPaymentType_EnumType)
  • PaymentAmnt (cfc:MonAmnt_Type)
AccountBalance Type: cfc:MonAmnt_Type
AccountType Values:
  • CRS1101 – Depository Account
  • CRS1102 – Custodial Account
  • CRS1103 – Cash Value Insurance or Annuity
  • CRS1104 – Debt or Equity Interest

Chapter 15: Joint Account (Page 55)

Diagram: Joint Account Structure Diagram
Page Reference: 55
Description: Structure for identifying joint account information. Shows details about multiple account holders.

JointAccount Type: xsd:complexType
Mandatory Child:
  • Number (integer, 1-200) – Number of joint account holders
